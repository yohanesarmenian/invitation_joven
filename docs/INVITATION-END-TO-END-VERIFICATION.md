# Hasil implementasi dan verifikasi undangan end-to-end

Tanggal: 16 Oktober 2026, Asia/Jakarta. Lingkup: task T00–T13 pada `INVITATION-END-TO-END-TASKS.md`. Implementasi dan automated QA diselesaikan secara lokal; **rehearsal kamera Android fisik masih menunggu pengujian owner**. iPhone tersedia tetapi owner memilih Android lebih dahulu. Ini bukan deployment atau persetujuan venue-ready.

## Perubahan implementasi

- Timing fold, stagger, entry, reveal dan fallback berasal dari `invitation-motion.ts`, diteruskan ke CSS melalui custom properties. Aturan timing Figma lama yang tertimpa dibersihkan.
- Amplop selesai berdasarkan `transitionend` transform lipatan terakhir; masuk konten selesai berdasarkan `animationend` milik container yang tepat. Timer terukur tetap tersedia jika end event hilang. Aktivasi berulang tidak melewati stage.
- Foto cover dipersiapkan di balik amplop. Penantian gambar dibatasi 3,5 detik. Jika hero dan fallback gagal, judul teks kembali terlihat dan tamu tetap dapat membuka konten.
- Tombol menunggu hydration sebelum menerima interaksi. Perubahan preferensi motion tidak lagi membersihkan timer aktif tanpa menyelesaikan stage. Reduced motion, toggle, penyimpanan pilihan, fokus keyboard dan perubahan storage diuji.
- Entry memakai pergerakan 24 px dan reveal 18 px, easing yang konsisten, serta jarak cover-exit lebih kecil. Observer yang tidak tersedia/gagal tidak meninggalkan konten tersembunyi. Form dan QR tidak dijadikan target reveal.
- Validasi origin development mengizinkan port loopback eksplisit melalui satu helper bersama. Request admin tetap harus cocok dengan configured origin; HTTP LAN/suffix host/protokol lain ditolak, produksi tetap membutuhkan HTTPS. Tidak ada perubahan otorisasi, CSRF, cookie, schema database atau kontrak API.
- Harness QA memakai port/output terpisah. Fixture pending benar-benar belum memiliki RSVP/pass; pass baru dihasilkan melalui submit UI. Mock regressions memakai port 3110/4110, real E2E memakai 3100/3101/4100, preview visual tetap 3000/4010.
- Helper `ops/local-journey.mjs` dan fixture privat menyediakan rehearsal lokal yang dapat diulang. Fixture menolak database di luar QA loopback, tidak menimpa file privat existing, dan cleanup hanya menghapus fixture miliknya. Startup dan cleanup melalui stdin sudah dijalankan; file privat berhasil dihapus.

Backend RSVP, messages, check-in, locking, scanner dan recovery sudah tersedia sebelum slice ini. Bukti di bawah adalah pengujian ulang terhadap implementasi nyata, bukan klaim bahwa semuanya baru ditulis pada sesi ini. Posisi foto, font, konten keluarga dan file aset tidak didesain ulang.

Public rendering baseline pada built localhost Chromium, cache image hangat, GPU dinonaktifkan pada harness: LCP **84 ms**, CLS **0,000678**, long tasks teramati **0**, script transfer **152.513 byte**. Ini satu sampel sintetis lokal; bukan SLA, pengukuran FPS animasi, jaminan Android, atau perbandingan before/after yang setara. CPU time dan peak process-family memory tidak diukur.

Percobaan awal unit test paralel gagal membuat worker; dijalankan ulang dengan satu worker dan lulus. Percobaan browser awal mengalami crash/timeout ketika host terbatas sumber daya dan aplikasi kemudian ditutup paksa oleh owner. Penyebab freeze aplikasi tidak didiagnosis pasti. Setelah restart, batas concurrency dan server QA terpisah, suite lulus. Lint pertama membaca output QA generated; folder tersebut kini di-ignore oleh ESLint. Kegagalan awal config origin, media preference dan fault-injection harness diperbaiki; hasil final dipisahkan dari percobaan gagal. Warning fallback-font TikTok Sans dan warning pg concurrent client query masih terlihat pada development harness; tidak menimbulkan kegagalan assertions.

Suite smoke lama dengan guard database persis `invitation_5c_smoke` **tidak dijalankan** pada QA baru. Guard tidak dilonggarkan. Coverage public lifecycle/persistence digabungkan dari API tests, public mock regressions dan vertical real E2E di atas.
